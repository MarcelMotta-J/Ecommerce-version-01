# 🧠 Diferença REAL

## 🔹 `compose.dev.yaml`

```text
💻 ambiente de DESENVOLVIMENTO
✔ usa volumes (código ao vivo)
✔ roda mvnw spring-boot:run
✔ hot reload
✔ debug fácil
```

👉 você altera código → já reflete

---

## 🔹 `compose.fullstack.yaml`

```text
📦 ambiente mais "PRODUÇÃO"
✔ usa build (Dockerfile)
✔ imagem fechada
✔ sem hot reload
✔ mais parecido com Render
```

👉 você precisa rebuildar para ver mudanças

---

# 🚀 Sobre os comandos

## 🔹 1. Com `--build`

```bash
docker compose -f compose.dev.yaml up --build
```

👉 força rebuild

Use quando:

```text
✔ mudou Dockerfile
✔ mudou dependência (pom.xml, package.json)
✔ deu bug estranho
```

---

## 🔹 2. Sem `--build`

```bash
docker compose -f compose.dev.yaml up
```

👉 mais rápido
👉 usa container já existente

Use quando:

```text
✔ só mudou código Java/Angular
✔ quer subir rápido
```

---

## 🔹 3. Com `-d`

```bash
docker compose -f compose.fullstack.yaml up -d --build
```

👉 roda em background (daemon)

```text
✔ não trava terminal
✔ ideal para ambiente mais estável
```

---

# 🧠 Regra de ouro

```text
dev.yaml     → usar SEMPRE no dia a dia
fullstack    → usar para simular produção
```

---

# 🎯 Resumo estilo capitão

```text
dev + up            → rápido 🚀
dev + up --build    → reset leve 🔧
fullstack + -d      → ambiente sério 📦
```

---

# 💡 Dica importante

Se o Docker começar a ficar “estranho”:

```bash
docker compose -f compose.dev.yaml down
docker compose -f compose.dev.yaml up --build
```
